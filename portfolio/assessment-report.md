# Application assessment: five legacy document-platform apps

Measured against [portfolio/rubric.md](rubric.md) at [`f57a3f76b`](https://github.com/Cognition-Partner-Workshops/otterworks/commit/f57a3f76be3d44aee6d352d2d293d8ddf75c8505) (tip of `demo-appassess`). The questionnaire answers in [app-inventory.csv](app-inventory.csv) were treated as claims to check, not as evidence. Every code link is pinned to that commit, and every traffic figure links to its exact query in [log-queries.md](log-queries.md). The one-row-per-app spreadsheet is [assessment-report.csv](assessment-report.csv).

> **The 90 days of access logs are synthetic.** Every row has `"synthetic": true`, and the files come from `scripts/appassess/generate-access-logs.py`. The traffic findings describe that fixture, not production telemetry.

| Application | Disposition | Questionnaire | Agrees |
|---|---|---|---|
| [legacy-portal](#legacy-portal) | **rearchitect** | rehost | **no** |

**Owner decision needed: db2-retention-archive gets no disposition.** It holds legal-hold and review-class retention records. Today they can be deleted by the PURGE stage, by tenant teardown or by the hourly reaper, and none of those paths asks a person. **Records Management** has to decide before anyone plans this migration.

Four of the five answers differ from the questionnaire. The fifth, legacy-share-links, has the right answer for the wrong reason.

## How this was assessed

- **Round 1:** one worker per app, read-only. Each read the app's own code, then everything that touches it: the gateway route matrix ([config.go:113-129](https://github.com/Cognition-Partner-Workshops/otterworks/blob/f57a3f76be3d44aee6d352d2d293d8ddf75c8505/services/api-gateway/internal/config/config.go#L113-L129)), deploy units (Compose, Helm, Terraform, CI), everything under `scripts/` and `migration/`, other services and frontends, and the 90 days of logs.
- **Round 2:** one worker per app, given all five round-1 reports. Each checked its app for shared databases, outside callers, data whose deletion someone must approve, and contradictions between workers.
- **Lead review:** I ran every log count myself ([commands and outputs](log-queries.md)), and confirmed the S3 copy matches the generator byte for byte ([command](log-queries.md#s3-copy-matches-the-generator)). I re-read every cited line at the pinned commit before using it, and made the final call on each app. Two of those calls differ from what the workers recommended; both are explained [below](#where-i-overrode-the-workers).

## What the cross-app round found

These sit outside each app's own folder and change the plan:

1. **One gateway change broke two apps.** [commit ab390f72f](https://github.com/Cognition-Partner-Workshops/otterworks/commit/ab390f72f) removed `/api/v1/reports` from ServiceRoutes. The 12,600 report-service requests in the logs all got a 404 because of it [log query: report-service](log-queries.md#report-service), and so do the admin-dashboard archive and reconciliation pages that read db2-retention-archive's data [frontend/admin-dashboard/src/app/core/services/migration-api.service.ts:82](https://github.com/Cognition-Partner-Workshops/otterworks/blob/f57a3f76be3d44aee6d352d2d293d8ddf75c8505/frontend/admin-dashboard/src/app/core/services/migration-api.service.ts#L82). That is why the questionnaire thinks nobody calls report-service.
2. **Two apps share legal-hold data.** report-service reads the archive's legal-hold records through a SELECT-only role [migration/target/postgresql/100_grants.sql:1-15](https://github.com/Cognition-Partner-Workshops/otterworks/blob/f57a3f76be3d44aee6d352d2d293d8ddf75c8505/migration/target/postgresql/100_grants.sql#L1-L15). In tenant and dev deploys, its own `reports` table sits in the same database as `arch.*` [scripts/lib/tenant-common.sh:381](https://github.com/Cognition-Partner-Workshops/otterworks/blob/f57a3f76be3d44aee6d352d2d293d8ddf75c8505/scripts/lib/tenant-common.sh#L381) [migration/target/postgresql/README.md:4-5](https://github.com/Cognition-Partner-Workshops/otterworks/blob/f57a3f76be3d44aee6d352d2d293d8ddf75c8505/migration/target/postgresql/README.md?plain=1#L4-L5). Teardown drops that whole database [scripts/lib/tenant-common.sh:236](https://github.com/Cognition-Partner-Workshops/otterworks/blob/f57a3f76be3d44aee6d352d2d293d8ddf75c8505/scripts/lib/tenant-common.sh#L236). Moving or dropping report-service's database would therefore take the archive with it.
3. **A nightly script still calls an app that nothing routes to.** `nightly-share-links-purge.sh` POSTs to legacy-share-links every night [scripts/nightly-share-links-purge.sh:2-8](https://github.com/Cognition-Partner-Workshops/otterworks/blob/f57a3f76be3d44aee6d352d2d293d8ddf75c8505/scripts/nightly-share-links-purge.sh#L2-L8). The app is not routed [services/api-gateway/internal/config/config.go:113-129](https://github.com/Cognition-Partner-Workshops/otterworks/blob/f57a3f76be3d44aee6d352d2d293d8ddf75c8505/services/api-gateway/internal/config/config.go#L113-L129) and not deployed [security/deps/modules.yaml:107-110](https://github.com/Cognition-Partner-Workshops/otterworks/blob/f57a3f76be3d44aee6d352d2d293d8ddf75c8505/security/deps/modules.yaml#L107-L110). That cron call is the app's only traffic.
4. **legacy-share-links shares a database name.** Its table defaults to the shared `otterworks` database [services/legacy-share-links/src/main/java/com/otterworks/sharelinks/Db.java:12](https://github.com/Cognition-Partner-Workshops/otterworks/blob/f57a3f76be3d44aee6d352d2d293d8ddf75c8505/services/legacy-share-links/src/main/java/com/otterworks/sharelinks/Db.java#L12), the same default auth-service and deploy-dev use [services/auth-service/src/main/resources/application.yml:10](https://github.com/Cognition-Partner-Workshops/otterworks/blob/f57a3f76be3d44aee6d352d2d293d8ddf75c8505/services/auth-service/src/main/resources/application.yml#L10) [scripts/deploy-dev.sh:219](https://github.com/Cognition-Partner-Workshops/otterworks/blob/f57a3f76be3d44aee6d352d2d293d8ddf75c8505/scripts/deploy-dev.sh#L219). ## Where I overrode the workers

- **report-service: replatform, not `none`.** The round-2 worker argued for `none` because report-service's database shares a home with `arch.*` in tenants. I disagree. Every tenant SQL service lives in that database [migration/target/postgresql/README.md:4-5](https://github.com/Cognition-Partner-Workshops/otterworks/blob/f57a3f76be3d44aee6d352d2d293d8ddf75c8505/migration/target/postgresql/README.md?plain=1#L4-L5), so sharing it doesn't make report-service the holder of the data. report-service only reads `arch.*` through a SELECT-only role [migration/target/postgresql/100_grants.sql:1-15](https://github.com/Cognition-Partner-Workshops/otterworks/blob/f57a3f76be3d44aee6d352d2d293d8ddf75c8505/migration/target/postgresql/100_grants.sql#L1-L15), and its own data is deleted without approval [services/report-service/src/main/java/com/otterworks/report/service/ReportService.java:125-135](https://github.com/Cognition-Partner-Workshops/otterworks/blob/f57a3f76be3d44aee6d352d2d293d8ddf75c8505/services/report-service/src/main/java/com/otterworks/report/service/ReportService.java#L125-L135). The data belongs to db2-retention-archive, which is flagged. The co-location becomes caveat 3: split the `reports` table into its own database before the move.
- **legacy-billing: replatform, not rearchitect.** Both rounds said rearchitect, because a recorded corpus exists for all four modules. The standard needs a corpus that *can prove each port*. Today only plans is mapped and approved. The other three report SKIP, and the human-approved rules gate has to pass before parity can grade them [procs/README.md:105-112](https://github.com/Cognition-Partner-Workshops/otterworks/blob/f57a3f76be3d44aee6d352d2d293d8ddf75c8505/procs/README.md?plain=1#L105-L112) [procs/routes.yaml:43-51](https://github.com/Cognition-Partner-Workshops/otterworks/blob/f57a3f76be3d44aee6d352d2d293d8ddf75c8505/procs/routes.yaml#L43-L51). Rearchitect is the next step, module by module, once each module has an approved ledger.
