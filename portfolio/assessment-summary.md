## Decisions

| Application | Questionnaire | Decision | Owner action |
|---|---|---|---|
| legacy-portal | rehost | **rearchitect** | Customer Portal: re-prove parity, name the `/portal/*` surface |

## Cross-app findings that changed a decision

- **report-service ↔ db2-retention-archive.** Retiring report-service would remove the reconciliation view Records Management needs before approving any purge. That alone blocks the questionnaire's retire.
- **legacy-billing ↔ shared RDS.** The billing worker's first proposal, "move to the shared RDS", conflicted with the version pin that report-service and the migration depend on. The billing target is now a dedicated PostgreSQL 16 instance.
- **Sequencing:** restore the report route, then Records Management decides on the archive, then readers switch off Db2. Portal, billing and share-links have no blocking dependency on each other.

## Method and limits

Five workers each gathered evidence for one app from code, routing, deployment, callers and logs. Five cross-checkers then each re-verified one app's citations against all five sets of findings. I spot-checked every line reference in the CSV against commit f57a3f76b.
**Limit:** this machine had no AWS credentials, so the logs were not read from `s3://otterworks-data-lake-dev/appassess/<run token>/access-logs/`. They were regenerated with the repo's deterministic generator ([scripts/appassess/generate-access-logs.py](https://github.com/Cognition-Partner-Workshops/otterworks/blob/f57a3f76be3d44aee6d352d2d293d8ddf75c8505/scripts/appassess/generate-access-logs.py)), which writes the same rows. Anyone with S3 access can rerun the queries below against the bucket to confirm. No application code was changed.
