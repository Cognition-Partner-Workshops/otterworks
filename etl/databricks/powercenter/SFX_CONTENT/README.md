# SFX_CONTENT SQL conversions

Run: `dbx-d1111`; expires: `2026-11-24`. Execute only on the provided serverless SQL warehouse.
All writes are confined to the run's after/parity/control schemas. The before schema is read-only.

```sh
make sfx-informatica-up NS=dbx-d1111-documents INFA_DB=teradata ROWS_PER_TABLE=2000 BUSINESS_DATE=20261109
# Bind DATABRICKS_HOST, DATABRICKS_TOKEN, DATABRICKS_WAREHOUSE_ID securely.
# TD_PORT is 54500 + crc32(NS) % 1000 (54702 for the namespace above).
export NS=dbx-d1111-documents TD_PORT=54702
etl/informatica/.venv/bin/python etl/databricks/powercenter/SFX_CONTENT/validate.py
etl/informatica/.venv/bin/python etl/databricks/powercenter/SFX_CONTENT/run_validation.py
etl/informatica/.venv/bin/python etl/databricks/powercenter/SFX_CONTENT/deploy_job.py
```

`validate.py` first proves input counts and canonical MD5 sums, including the flat files,
then runs the unmodified PowerCenter `startsession` command for each mapping. Each oracle
session starts from the frozen live staging inputs; the workflow is validated separately.
`run_validation.py` loads tagged oracle tables and compares complete physical target rows,
counts, MD5 sums and up to 20 `EXCEPT ALL` differences each way. It executes each conversion
twice and compares the second run with the first snapshot. Raw rows and API responses stay
in ignored `local-evidence/`. Public statement identifiers and summaries are in `evidence.json`.
Validation setup explicitly resets only these five after targets from their proven before
targets; run it before conversions, never between the two idempotence executions. This avoids
trusting pre-existing after state. The job does not run validation setup or reset its targets.
Rejected rows are compared with the runner's BadFiles on the complete connected column set.

CHAR columns imported as padded STRINGs are normalized only where the legacy reader strips
CHAR padding. NULL uses the explicit `<NULL>` canonical token; dates use ISO formatting.
The first unnormalized hash failures are retained alongside corrected results.
Staging APP_USER truncates its input DISPLAY_NAME port to 60 before trimming; direct APP_USER
does not silently truncate the VARCHAR target. Its 100 overlength rows are retained in
`users__app_user__reject`, matching the runner's reject file. Session `Stop on errors=0`
means those rejects do not fail the session. Idempotent MERGEs suppress unchanged updates.
DOCUMENT retains the unconnected physical FILE_TYPE on updates; staging sets it to NULL.

Lookup caches use ROW_NUMBER ordered by the same key the runner orders on. Cache probes with
NULL keys cannot match. Divergent values tied on a non-unique lookup key fail explicitly
because the runner supplies no stable tie order. Filter conditions use COALESCE(...,false).
IIF and DECODE(TRUE,...) use CASE WHEN, where NULL conditions are false. All five XMLs were
inspected: none contains a Sequence Generator or Router. The Router belongs to reserved
LOGIN_EVENT; the Sequence Generator belongs to SFX_BILLING/GL_JOURNAL_LINE. Neither is converted here.

The job uses the same conversions with APP_USER and DOCUMENT reading their in-job upstream
targets (`job-sql/`, generated by `deploy_job.py`). Every enabled in-scope WORKFLOWLINK is
represented by ALL_SUCCESS dependencies. Reserved ROLE_GRANT is a second required predecessor
of DOC_SHARE. Its explicit dependency gate fails, leaving DOC_SHARE unrun in the job: this
partial workflow cannot claim success until the separate program supplies that predecessor.
The standalone DOC_SHARE parity uses the proven frozen ROLE_GRANT lookup, without writing it.
Reserved LOGIN_EVENT is an excluded sibling; TEAM_MEMBER is disabled and excluded. No worklet,
decision or email task appears in this workflow.

Cross-folder dependencies: none. All five mappings, lookup owners and workflow callers are
inside SFX_CONTENT. There is no billing/customer lookup despite DOCUMENT.CUSTOMER_ID.
The shared warehouse seed and runner are execution dependencies, not converted mappings.
SFX_AUDIT reads its own staging inputs and has no caller or lookup into these five mappings.

`collect_evidence.py` publishes aggregate evidence without source rows. DOC_SHARE is red for
workflow release even though its standalone parity passes: its reserved predecessor remains
unsatisfied. Four green mappings contribute to the global licence counter; this PR does not
claim that shared PowerCenter options can be cancelled while remaining mappings use them.
Job tags are verified through Jobs GET; each run also records run_token, expires and act as
job parameters (the Runs GET API does not expose a separate run tags field).

After opening the PR, publish only these five inventory rows:

```sh
etl/informatica/.venv/bin/python etl/databricks/powercenter/SFX_CONTENT/collect_evidence.py
etl/informatica/.venv/bin/python etl/databricks/powercenter/SFX_CONTENT/publish_control.py --pr "$PR_URL"
```

`publish_control.py` resolves existing object identities by source_path, adds only absent
evidence columns and MERGEs on both object_name and source_path. It never replaces inventory
rows or changes reserved mappings. `query_history.sql` can be rerun after ingestion catches up;
unmatched statement IDs retain direct Statement Execution evidence and are labelled pending.
