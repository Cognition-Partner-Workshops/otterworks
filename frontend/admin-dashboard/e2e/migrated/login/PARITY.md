# Parity: Selenium `LoginTest` → Playwright `login/login.spec.ts`

Legacy source: `tests/legacy-suites/selenium/src/test/java/com/otterworks/legacy/admin/tests/LoginTest.java`
(supporting: `tests/AdminTestBase.java`, `pages/BasePage.java`, `pages/LoginPage.java`, `pom.xml`), branch
`qe/legacy-suites-fixture`, run unmodified with
`ADMIN_BASE_URL=http://localhost:4200 mvn -s frontend/admin-dashboard/e2e/migrated/stack/maven-settings.xml test -Dtest=LoginTest`
(Maven 3.9.9, Java 17, Selenium Manager Chrome/ChromeDriver 156, headless) against `ng serve` :4200 with the
real Compose stack up. Two runs: 3 tests, 0 failures each.

Playwright: `npm run test:e2e:migrated -- --grep @selenium-LoginTest` against the same stack, two runs in a
row, 3 passed each.

The login screen is public and its three behaviours are client-side (Angular component state), so none of
these tests needs a seeded user or a session: the fixtures deliberately do not request `adminSession`
(its stored token would make `LoginComponent` redirect away from `/login`). No `page.route` mocks.
