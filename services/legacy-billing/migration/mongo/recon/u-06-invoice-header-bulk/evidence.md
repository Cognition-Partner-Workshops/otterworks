## Root cause: spec/loader field mismatch (not a data gap)

map-draft-3 scopes the `lines` embed on the target side with
`{"lines.invoiceId": {"$exists": true}}` and maps `INVOICE_ID → invoiceId` in
`child_fields`. The accepted loader
(`services/legacy-billing/migration/mongo/load_invoice_header.py`) uses
INVOICE_ID only as the embed parent key and **never persists `invoiceId` inside
line elements** — verified on the loaded target:

- `count_documents({})` = 18750
- `count_documents({"lines.invoiceId": {"$exists": true}})` = **0**
- `sum($size lines)` = 149963 (max 23/doc), only collection in
  `ow_billing_migration` is `invoiceHeader`

So the target-side scoped population is 0 by construction, while the source
side is 149963 (= 150000 INVOICE_LINE − 37 `orphan_line` quarantine). The
harness-reported delta is therefore the full 149963.

**This is a spec-content issue for the orchestrator / human (STOP B / D-018
follow-up); not fixed here per instructions.** Candidate resolutions, stated
neutrally:

1. Spec: a `target_where` matching the loader's document shape — e.g. `"{}"`
   (as the earlier diagnostic copy used) or a predicate on a field the
   elements actually carry, such as `lines.lineId`.
2. Loader: persist `invoiceId` into embedded elements (a loader change).

**The 37-row orphan gap is NOT cleared by this run** — it is masked inside the
149963-vs-0 mismatch. The prior diagnostic run (map-draft-2 subset +
`child_where`/`target_where: "{}"`) remains the only all-tiers PASS and stays
labelled diagnostic under `diagnostic-child_where/` (untouched, historical).

## PROFILE FEEDBACK (rules derived, not in the profile/mapping)

1. Embed with a quarantined orphan child: the harness has no quarantine-aware
   exclusion; the only lever is `embeds[].child_where` + `target_where` in the
   mapping, which is a spec change.
2. `child_where` must be spelled with the child alias
   (`invoice_id IN (SELECT invoice_id FROM invoice_header)`); `target_where`
   is a JSON string (`"{}"` when the target has no extras).
3. **`target_where` must reference a field the loader actually persists inside
   the elements.** `{"lines.invoiceId": {"$exists": true}}` selects 0 docs
   here because `invoiceId` is the parent key only and is never stored in
   `lines[]`; a scoping predicate has to name a persisted field (e.g.
   `lines.lineId`) or be `"{}"`.
4. `lines[]` ordering: seed duplicates `(invoice_id, line_no)`; sort by
   `(lineNo, lineId)` for a byte-identical reload.
5. Month-end totals: Oracle `FM...0.00` == Python `Decimal.quantize(0.01)`
   rendered with `format(d, "f")`; `UNKNOWN()` for NULL `status_cd`
   (Oracle `TO_CHAR(NULL)` is empty).
6. `$dateToString` `%b` is not portable; compare dates as BSON dates with
   `datetime_utc_truncate_ms`.
7. The harness Tier 4 replays `source_sql` on the same single Oracle
   connection, so one `--ops` file per unit is enough within
   `--source-concurrency 1`.
8. A where-scoped embed makes the harness report the "extra target elements
   not checked" warning on a PASS, and harness `merge_eligible` is false
   regardless (fixture/local is never merge evidence — known limitation).
