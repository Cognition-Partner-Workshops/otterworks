# Kubernetes 1.35 API compatibility — dev fleet

**RED for the full fixture set:** the standalone `file-service` PodDisruptionBudget uses `policy/v1beta1`, removed in Kubernetes **1.25**. The six desired Helm releases and their two local controls use only APIs served by Kubernetes 1.35. This is an offline API-version check, not rollout or upgrade approval. No cluster or manifest changes were made.

Source: `origin/demo-devops` at `95273d7c5ce14ced2f4d43e5376edf76262292eb`; local synthetic fleet, namespace `devops-fleet`. The [deployment snapshot](../fixtures/observed-deployments.json) is from local kind, not AWS.

## Decisions and recommendations

- **file-service (storage):** Keep the compatibility case red. Leave the deliberately legacy [fixture](../fixtures/legacy-api.yaml) intact as a negative control. Before using a real file-service PDB on 1.35, use a separate `policy/v1` manifest with an explicit workload selector, validate it with a server-side dry run against disposable 1.35 dev, and review the effect of `minAvailable: 1` on voluntary disruption of a single replica.
- **collab-service:** Desired state names collaboration, but the recorded running Deployment has no owner label. Leave it unchanged; confirm with the collaboration team before convergence or restart. Obtain explicitly approved restart tolerance and windows wherever missing; a Deployment strategy or HPA does not establish them.
- **Shared add-ons (recorded AWS snapshot, not live):** The [synthetic inventory](../fixtures/eks-addons.json) lists vpc-cni as compatible with 1.35, but lists only 1.34 for CoreDNS and kube-proxy. CoreDNS has no recorded maintenance window; the ingress controller is absent from the inventory, not a pass. Ask platform-runtime to verify supported CoreDNS/kube-proxy versions and approve a window, and identify the ingress controller owner and version before treating the add-on gate as cleared. No add-ons were changed or queried in AWS.

## Reproduce

From the repository root, with Helm 3.19.5, Pluto 5.23.0, and Python with `platform/standards/fleet/requirements.txt` installed:

```bash
out="$HOME/.devin-files/fleet-api-135"
mkdir -p "$out"
for workload in api-gateway auth-service collab-service document-service file-service search-service; do
  helm template "$workload" platform/standards/helm/app --kube-version 1.35.0 \
    --include-crds --namespace devops-fleet -f demos/devops/values/common.yaml \
    -f "demos/devops/values/$workload.yaml" || exit
done > "$out/rendered.yaml"
{ cat "$out/rendered.yaml"; printf '\n---\n'; cat demos/devops/kind/controls.yaml; } > "$out/desired.yaml"
{ cat "$out/desired.yaml"; printf '\n---\n'; cat demos/devops/fixtures/legacy-api.yaml; } > "$out/combined.yaml"
helm template api-gateway platform/standards/helm/app --kube-version 1.35.0 \
  --include-crds --namespace devops-fleet -f demos/devops/values/common.yaml \
  -f demos/devops/values/api-gateway.yaml -f demos/devops/values/api-gateway-observed.yaml \
  > "$out/gateway-observed.yaml"
curl -fsSL https://github.com/kubernetes-sigs/metrics-server/releases/download/v0.8.1/components.yaml \
  > "$out/metrics-server.yaml"

# The combined case intentionally exits nonzero in both scanners; capture both exit codes.
for scan in desired combined gateway-observed metrics-server; do
  ns=devops-fleet
  if [ "$scan" = metrics-server ]; then ns=kube-system; fi
  python platform/standards/fleet/fleet.py api "$out/$scan.yaml" --target 1.35 --namespace "$ns" \
    --markdown "$out/$scan.md" --json "$out/$scan.json"
  printf '%s: fleet exit=%s\n' "$scan" "$?"
  python -c 'import json,sys; d=json.load(open(sys.argv[1])); print(d["counts"]); print(*[r for r in d["resources"] if r["status"] != "no_catalog_finding"], sep="\n")' "$out/$scan.json"
  pluto detect "$out/$scan.yaml" --target-versions k8s=v1.35.0
  printf '%s: Pluto exit=%s\n' "$scan" "$?"
done
```

## Manual cross-check

The upstream [deprecation guide](https://kubernetes.io/docs/reference/using-api/deprecation-guide/) lists removal sections for 1.32, 1.29, 1.27, 1.26, 1.25, 1.22 and 1.16; it has no 1.33–1.35 removal sections. The [1.33](https://github.com/kubernetes/kubernetes/blob/master/CHANGELOG/CHANGELOG-1.33.md), [1.34](https://github.com/kubernetes/kubernetes/blob/master/CHANGELOG/CHANGELOG-1.34.md) and [1.35](https://github.com/kubernetes/kubernetes/blob/master/CHANGELOG/CHANGELOG-1.35.md) changelogs supplement it: 1.33 removed inactive authentication alpha serving code and alpha ValidatingAdmissionPolicy/Binding; 1.34 removed the formerly served `resource.k8s.io/v1alpha3` DRA kinds except DeviceTaintRule; 1.35 removed alpha StorageVersionMigration and `storage.k8s.io/v1alpha1` VolumeAttributesClass. None appear in the inputs. Core `v1` Endpoints was deprecated in 1.33, not removed in 1.35; it is not rendered here.

```bash
curl -fsSL https://raw.githubusercontent.com/kubernetes/website/main/content/en/docs/reference/using-api/deprecation-guide.md | awk '/^### v/{print}'
for n in 33 34 35; do
  curl -fsSL "https://raw.githubusercontent.com/kubernetes/kubernetes/master/CHANGELOG/CHANGELOG-1.$n.md" |
    rg -i '(inactive serving code|removed support for .?v1alpha1|DRA API: resource.k8s.io/v1alpha3|StorageVersionMigration.*removed|VolumeAttributesClass API is no longer served)'
done
curl -fsSL https://raw.githubusercontent.com/kubernetes/kubernetes/v1.35.0/api/openapi-spec/swagger.json |
  python -c 'import json,sys; d=json.load(sys.stdin); paths=d["paths"]; print("OpenAPI",d["info"]["version"]); print(*[f"{p}: {p in paths}" for p in ("/api/v1/namespaces/{namespace}/services","/apis/apps/v1/namespaces/{namespace}/deployments","/apis/networking.k8s.io/v1/namespaces/{namespace}/networkpolicies","/apis/policy/v1/namespaces/{namespace}/poddisruptionbudgets","/apis/autoscaling/v2/namespaces/{namespace}/horizontalpodautoscalers","/apis/policy/v1beta1/namespaces/{namespace}/poddisruptionbudgets")], sep="\n")'
```

The OpenAPI document is from the upstream **v1.35.0 tag** despite its `unversioned` metadata. The five served paths cover all GVKs in the desired dev input. The kind `Cluster` definitions configure the kind CLI and are not Kubernetes API objects. The Metrics Server `APIService` itself uses `apiregistration.k8s.io/v1`; this check does not test its aggregated endpoint or runtime behavior. No server-side admission or schema validation was run.
