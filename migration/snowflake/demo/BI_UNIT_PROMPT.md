# Tableau workbook prompt

Replace `<workbook>`, `<run-token>` and `<run-branch>` before you launch the session. The demo uses `Storage Overage`.

> Migrate the Tableau workbook `<workbook>` from SQL Server to Snowflake in `otterworks`. Read `migration/snowflake/AGENTS.md`, then open `migration/snowflake/source/tableau/<workbook>.twb` and its entry in `migration/snowflake/gate/bi/workbooks.yaml`. Branch `bi/<workbook>` off `<run-branch>`. Trace every datasource to its SSRS report in `source/reports/` and to the procedures behind its tables, and list that lineage in the PR. For each unit in the workbook's `units` list that `gate/out/ledger.md` doesn't show as PASS, port the procedure to dbt in `target/dbt/models/marts/<unit>.sql`. Bring up SQL Server with `make sfm-up` and prove the units with `make sfm-dual-run RUN=<run-token> DATE=2026-09-15`, then with `DATE=2026-09-30`. Then write `migration/snowflake/target/tableau/<workbook>.twb` as described in `target/tableau/README.md`, and run `make sfm-bi-parity RUN=<run-token> DATE=<date> WORKBOOK="<workbook>"` after the dual run for each date. Every datasource has to show PASS on both dates. If a sheet differs, fix the dbt model or the Snowflake SQL. Never touch the legacy workbook, the reports, the procedures or the contract. Stop after three full attempts and report what still differs. Open a PR into `<run-branch>` with the lineage, the ledger rows and a screenshot of `gate/out/bi/<slug>.html` for each date. Don't merge it.
