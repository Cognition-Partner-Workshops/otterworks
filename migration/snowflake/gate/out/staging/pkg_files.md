### Business decisions

Explanation: The staging model keeps five things pkg_files does, so the rows match stg.stg_files exactly (PASS 25000 / 25000 on 2026-09-30; the package ignores BusinessDate and truncates each run, so there is no date or watermark dependence). (1) Size rounding: the Script Task "SCR Convert sizes to MB" stores size_mb = ROUND(size_bytes / 1048576.0, 3), i.e. binary mebibytes labelled "MB", rounded to 3 decimals. 24,999 of 25,000 rows lose up to 524 bytes each; the column total is 20,820,693.389 against an exact 20,820,693.416. A correct version keeps size_bytes as the only stored size and derives MB/GB (decimal or binary, as the billing contract says) at full precision in the marts. The Snowpark procedure OPS.SSIS_PKG_FILES reproduces the task and agrees with SQL Server and the model on all 25,000 rows. (2) Missing archived flag: an empty archived field lands as NULL (750 rows: 712 not trashed, 38 trashed), and usp_load_dim_file copies that NULL to dim_file, where it is later counted as active. A correct version would have the data owners pick an explicit default (e.g. not archived) or flag the rows as unknown. (3) Trashed flag: is_trashed is true only for the exact lowercase string "true"; anything else, including empty or "TRUE", silently becomes false. Today every value is "true" (1,250) or "false" (23,750), so 0 rows are touched; a correct version would parse case-insensitively and reject unexpected values. (4) Tenant lookup: LKP Tenant from workspace reads SELECT DISTINCT workspace_id, tenant_id FROM stg.stg_auth_workspace_members; a file whose workspace has no member row keeps its row with tenant_id NULL instead of failing or being redirected, and a workspace with two tenants would take whichever the cache keeps. Today 0 files miss and 0 workspaces have more than one tenant (guarded by tests/pkg_files__workspace_single_tenant.sql); a correct version would resolve tenant from an authoritative workspace table and quarantine unmatched files. (5) Empty folder: an empty folder_id lands as NULL (5,000 root-level files); a correct version would make "no folder" explicit if anything downstream groups by folder.
