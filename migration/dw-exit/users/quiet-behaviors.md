# Users quiet-behavior audit

Scope: all 55 users manifest objects; source files are unchanged. Measurements below
are from local PostgreSQL `sfx-1120-before`, 200-row fixture generation, business date
`20261109`, and the actual PC capture in `.runs/pc-users-sessions/`. They are not
observations of production Teradata or Snowflake. SQL/dbt/Snowpark preservation claims
are static unless an explicit local measurement is given. No live Snowflake execution.

## Interpretation / checks

No audit finding authorizes a behavioral change. The only owner approval is the
200-character display name. Local board greens concern the declared independent outputs,
not scheduler equivalence, error-file contents, enforced Snowflake keys, locale behavior,
JDBC side tables, or live Snowpark execution. See `shared-surfaces.md` for cross-area effects.

The data checks used `COUNT(*)-COUNT(DISTINCT row(t.*))`, first-column duplicate counts,
`pg_indexes` for lookup enforcement, `length(staging.field)>legacy_width`, CHAR
`octet_length(field)>octet_length(rtrim(field))`, and result-code GROUP BY in local PG.
Spark fallback/isolated metrics were computed directly from the captured landing PSVs.
The actual-PC log explicitly distinguishes the disabled workflow task from its standalone
execution. Adversarial rows are tests, not claims that those branches fired in this capture.
