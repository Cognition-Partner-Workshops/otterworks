## 7. Error paths

- **Fault handler:** `catchAll` → sequence `RollbackAndRedeliver` → `RejectDelivery` (`bw.jms.JMSConfirm`) with `acknowledge=false`, `maxRedelivery=3`, `undeliveredQueue=HB.UNDLV` [`integration/legacy-bw6/Processes/statements-documents/statement-drop.bwp:L5-L7`](../../../../legacy-bw6/Processes/statements-documents/statement-drop.bwp#L5-L7). `EmsConnection` repeats `maxRedelivery=3` and `HB.UNDLV` [`integration/legacy-bw6/SharedResources/EmsConnection.sharedresource:L2`](../../../../legacy-bw6/SharedResources/EmsConnection.sharedresource#L2).
- **Ambiguity:** the handler is a JMS confirm, but the starter is an SFTP get (section 2). What "redeliver" means for a picked-up file, and whether a failed file goes to `HB.UNDLV`, cannot be determined from the project. **Inference.**
- **The test broker:** the test broker's address settings use `HB.UNDLV` as the dead-letter address, with `max-delivery-attempts=4` and `redelivery-delay=100` [`integration/fixture/broker.xml:L20-L21`](../../../../fixture/broker.xml#L20-L21).
- **Work already done when a later step fails (Inference from sections 3-4):**
  - The insert auto-commits. A failure in the SFTP put, the publish or any callee leaves the `statement_jobs` row behind.
  - A retry of the same request then hits `PRIMARY KEY (flow, request_id)` [`integration/legacy-bw6/Database/schema.sql:L158`](../../../../legacy-bw6/Database/schema.sql#L158) and faults again.
  - If the file was already written, a retry fails on `overwrite=false` [`integration/legacy-bw6/Processes/statements-documents/statement-drop.bwp:L29`](../../../../legacy-bw6/Processes/statements-documents/statement-drop.bwp#L29).
  - If a callee faults after `Publish`, `HB.STATEMENT.READY` has already been sent [`integration/legacy-bw6/Processes/statements-documents/statement-drop.bwp:L34`](../../../../legacy-bw6/Processes/statements-documents/statement-drop.bwp#L34).
