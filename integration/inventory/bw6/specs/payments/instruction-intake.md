## 7. Error paths

- Process-level `catchAll` → sequence `RollbackAndRedeliver` → `RejectDelivery` (`bw.jms.JMSConfirm`) with `acknowledge=false`, `maxRedelivery=3`, `undeliveredQueue=HB.UNDLV` [`integration/legacy-bw6/Processes/payments/instruction-intake.bwp:L5-L10`](../../../../legacy-bw6/Processes/payments/instruction-intake.bwp#L5-L10). The same values are on EmsConnection [`integration/legacy-bw6/SharedResources/EmsConnection.sharedresource:L2`](../../../../legacy-bw6/SharedResources/EmsConnection.sharedresource#L2).
- Test broker: dead-letter address `HB.UNDLV`, `max-delivery-attempts` 4, `redelivery-delay` 100 [`integration/fixture/broker.xml:L20-L21`](../../../../fixture/broker.xml#L20-L21). That is 1 delivery plus 3 redeliveries, consistent with maxRedelivery 3.
- The scope itself has no fault handler (the scope element has no faultHandlers child [`integration/legacy-bw6/Processes/payments/instruction-intake.bwp:L12-L13`](../../../../legacy-bw6/Processes/payments/instruction-intake.bwp#L12-L13)), so faults inside it reach the process `catchAll`.
- **A fault inside `PostingTransaction`:** **Inference:** the XA transaction rolls back (no inbox/ledger rows, no status message) and the message is redelivered up to 3 times, then moved to `HB.UNDLV`.
- **A fault in a call-process step (after the scope committed):** **Inference:** the inbox/ledger rows and the `HB.PAYMENT.STATUS` message are already committed. `RejectDelivery` then runs for a message whose consumption was already committed. Two outcomes are possible: (a) no redelivery, so the remaining callees never run, or (b) redelivery. Under (b) the scope re-runs, the `payment_inbox` insert hits a primary-key violation on `(flow, request_id)` [`integration/legacy-bw6/Database/schema.sql:L8`](../../../../legacy-bw6/Database/schema.sql#L8), the XA scope rolls back, and the message eventually goes to `HB.UNDLV` while the first status message stays published. The project does not say which behaviour BW exhibits.
- Callees that already ran (for example validation-enrichment's `AUTO_COMMIT` row) are not compensated. No compensation handler is present in the project [`integration/legacy-bw6/Processes/payments/instruction-intake.bwp:L1-L62`](../../../../legacy-bw6/Processes/payments/instruction-intake.bwp#L1-L62).
