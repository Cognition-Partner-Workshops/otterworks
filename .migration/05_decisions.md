## §3 NOT verified

What the wave-1 `PASS` (16/16 units live under `map-draft-4`, `recon/wave-1/grade.json`) does **not** attest. Each item names the finding that explains why and where the gap is picked up (parallel-run / cutover / next model step), per the board's run plan.

1. **Zero-row units — `billingAuditLog`, `customerMasterHist`, `subscriptionsHist`** (F70, F73). `rows=0 vs docs=0` grades `PASS` / `merge_eligible: true`; composite keys `[custId, histId]` / `[id, histId]`, the `document_versioning` shape, every field rule and the trigger-cascade reconciliation `subscriptionsHist` exists for are unexercised. `billingAuditLog` was never even created on the target (no index declared); `customerMasterHist` exists empty with its unique index. The verifier marks the three `UNVERIFIED` (`recon/wave-1/verify-result.json`). Needs a populated source (a fixture that updates `SUBSCRIPTIONS` / `CUSTOMER_MASTER`, or parallel-run traffic) — deferred to parallel-run.
2. **Latent `histDt` format** (F73, §2 items 1 and 12). Both `*Hist.histDt` map `date` with the bare `date_string_to_date` (default `%d-%b-%y`) while the only writers produce `DD-MON-YY HH24:MI:SS`; every real history row would fail `!unconverted` in harness and loader alike. Not corrected (no spec edit in a batch ticket); the next model step must set `format: "%d-%b-%y %H:%M:%S"` before any populated source is used.
3. **Orphan sink `mmp_rt_b3_oracle.invoice_lines_orphaned` is graded by hand only** (F69, F71, F72; F47, F57). Under `child_where` the harness grades 1,463 of 1,500 `INVOICE_LINE` rows and never sees the 37 ghost-invoice lines; the sink is not a spec collection, cannot be a wave write target, and `invoiceHeader` can never be `merge_eligible` with a scoped embed. Parallel-run must re-count the sink against the source predicate.
4. **Shared-principal target and the `online` policy — `d-target-principal`** (F12, F13, F58). `connectivity.json` says `target.blocked: true` (`privilege_excess`: `MONGODB_ATLAS_URI` holds `readWriteAnyDatabase@admin` + `dbAdminAnyDatabase@admin`); the policy was never switched to `auto`, no database-scoped Atlas user was created, and preflight never reads `connectivity.json`.
