## Decisions applied (facts, not proposals)

| ID  | Decision (as applied to U1) |
|-----|-----------------------------|
| D1  | Namespace: every document carries `ns: "mongo_205236"`; target DB `ow_tp_mongodb_205236`, quarantine DB `ow_tp_mongodb_205236_quarantine`. |
| D2  | Keys: `CUSTOMER_MASTER.CUST_ID -> customers._id` (string UUID); `CUSTOMER_MASTER_HIST.HIST_ID -> customers_history._id` (Int64). |
| D3  | String dates (`SIGNUP_DT`, `LAST_ACTIVITY_DT`, `UDF_DT_*`, EAV `CREATED_DT`) are carried verbatim and graded verbatim. Derived BSON-date twins `signup_date` / `last_activity_date` are added when `DD-MON-YY` parses strictly; unparseable values leave the twin `null` and emit quarantine class `dirty_signup_dt` (only `SIGNUP_DT` is a graded quarantine class; 50 expected in fixture). |
| D4  | CSV lists (`RELATED_ACCT_IDS`, `CHILD_ACCT_IDS`, `PROMO_CODES_CSV`) are carried verbatim and graded verbatim. Derived array twins `related_accounts` / `child_accounts` / `promo_codes` = split on `,`, strip, drop empties. Malformed = empty token inside a non-empty list, or a token containing characters outside `[A-Za-z0-9_-]`; malformed values keep the verbatim string, get a `null` array twin, and emit quarantine class `bad_csv_list` (31 expected). |
| D5  | `ENTITY_ATTR_VALUE` (`entity_type='CUSTOMER'`) folds into `customers.attributes[]`; element key `eav_id`; graded fields `eav_id, entity_type, entity_id, attr_name, attr_value, attr_type, created_dt`; order by `eav_id`. Population 8,333; orphans (no parent in batch) are 0 in fixture and would be quarantined, never dropped silently. |
| D6  | Wide table: all 155 `CUSTOMER_MASTER` columns are carried as lower_snake_case fields; nulls are explicit (`null`), never omitted. |
| D7  | Types: `NUMBER(p,0)` p<=9 -> int32; p>9 -> Int64; `NUMBER(14,2)` -> Decimal128 rounded half-even at scale 2; Oracle `DATE` -> BSON date (UTC, no tz shift); `CHAR` -> rstrip spaces; `VARCHAR2` -> string, empty string is null. |
| D8  | Derived read-model helpers: `addresses {billing, mailing}` and `phones[] {number, type_cd}` are added alongside (not instead of) the flat source fields; derived paths are unexercised by recon and declared so. |
| D9  | Root scope: `conversion_batch_no = ${batch_no}` (85559852 for fixture ns `demo`). |
| D10 | `CUSTOMER_MASTER_HIST` -> `customers_history`: created empty (0 rows) with `_id` = `HIST_ID`; graded as an empty collection (count 0 == 0). |
| D11 | Sequences -> `counters` documents `{_id: <SEQUENCE_NAME lower>, seq: Int64(LAST_NUMBER), ns}` seeded from the census: `seq_customer_master 125000`, `seq_customer_master_hist 1`, `seq_entity_attr_value 11001`. Allocation is `findOneAndUpdate($inc)` returning the new value. |
| D12 | Trigger behaviour moves to the app write path (`services/legacy-billing/app/customer_writes.py`): `TRG_CUSTOMER_MASTER_SEQ` -> allocate `cust_seq_no` when missing, `cust_name_upper = upper(cust_name)`, `row_version_no` defaults to 1; `TRG_CUSTOMER_MASTER_HIST` -> on update/delete append the full prior document to `customers_history` with `hist_op UPD|DEL`, `hist_dt` and `_id` from `seq_customer_master_hist`; `TRG_ENTITY_ATTR_VALUE_SEQ` -> allocate `eav_id` from `seq_entity_attr_value` when appending an attribute. |
| D13 | RPT-114 `BALANCES_SQL` is rewritten as a `$match {conversion_batch_no, ns}` + `$group` aggregation over `customers`; totals are formatted with the existing `FM999999999999990.00` convention; unavailable target -> 503 fail-closed as today. |

## Write targets (registered in 04_progress.md)

`ow_tp_mongodb_205236_quarantine.dirty_signup_dt`, `.bad_csv_list`.

`counters`: `_id` only. `customers_history`: `(cust_id, hist_dt)`.

## Grading

Recon: `run_mode: fixture`, family `oracle`, `--unit U1`, seed 714559852, params
`batch_no=85559852 source_ns=demo`. Graded paths: every source column on `customers`
(verbatim), `attributes[]` keyed by `eav_id`, `customers_history` count, `counters` seeded values.
Declared-unexercised: derived twins (`signup_date`, `last_activity_date`, `related_accounts`, `child_accounts`, `promo_codes`), `addresses`, `phones[]`, app write path.

INVOICE_* (U2), documents (U3), file metadata (U4) are untouched.
